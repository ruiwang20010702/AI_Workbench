# CONSENSUS：周报自动生成功能

## 明确需求与验收标准
1) 自动聚合一周工作数据
- 验收：支持按 `week_start/week_end` 聚合内部任务与项目数据；可选 Git 提交统计；日历数据占位实现无阻塞。
2) 模板系统与导出
- 验收：可创建/编辑模板（Markdown/Docx）；渲染预览成功；可一键生成并下载 Markdown/Docx；占位符校验返回具体错误。
3) AI 集成与优化
- 验收：支持对周报段落进行语法与风格优化；自动生成改进建议列表（含优先级）；失败时不影响原始周报输出。
4) 前后端分离与 API 文档
- 验收：端点完整（周报生成/历史/详情、模板 CRUD、AI 优化/建议）；统一鉴权与错误处理；接口返回结构稳定。
5) 数据安全与隐私
- 验收：第三方密钥使用环境变量；数据最小化与可选脱敏；导出链接权限控制或有效期。
6) 用户体验
- 验收：一键生成与预览；模板管理交互直观；历史周报列表与详情可用；基础数据可视化（本周完成率/工时统计）。

## 技术实现方案与约束
- 方案：后端 `Express + TS`；服务层 `ReportService/TemplateEngine/DocxGen`；Connector 插件化；前端 React 组件化；AI 复用现有 `AIService`。
- 约束：首期仅实现内部数据与 Git 统计；日历为占位；Word 样式为基础版；时序预测暂维持启发式，后续引入 Prophet（与 `FINAL` 文档一致）。

## 任务边界与验收
- 边界：不实现完整审批流与富格式企业模板；不做复杂跨平台 OAuth 流程；不引入重型时序模型；
- 验收：满足上述功能点与 API 契约；构建通过；基础测试覆盖；文档同步。

## 不确定性解决确认
- 周定义/时区、外部平台选择、模板规范、审阅流程与脱敏策略均已给出默认决策与可配置入口；后续按配置文件与 UI 设置实现。
