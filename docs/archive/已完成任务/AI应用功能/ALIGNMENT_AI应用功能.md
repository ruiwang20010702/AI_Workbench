# ALIGNMENT — AI应用功能

## 原始需求与目标

- 为现有工作台新增 AI 应用能力，围绕以下方向：
  - 智能推荐（基于用户行为与内容的个性化建议）
  - 自然语言处理（聊天助手、文本生成/改写/翻译/分析）
  - 计算机视觉（图像识别、内容审核）
  - 预测分析（趋势预测、异常检测）
- 已部署与环境：前后端均在 Vercel，数据库在 Supabase。

## 项目上下文与架构分析

- 技术栈
  - 后端：Node.js + Express（TypeScript），控制器/服务/模型分层；AI 路由已存在。
  - 前端：React + Vite（TypeScript），`aiService` 已集成生成/改写/翻译/分析等方法与设置页模型选择。
  - 数据库：Supabase（Postgres）；模型层覆盖用户、笔记、任务、项目等，具备统计与检索能力。

- 现有 AI 能力（服务端）
  - `AIService.generateText/translate/rewrite/analyze/generateEmbedding` 等方法，支持 SiliconFlow/OpenAI。
  - `aiController` 提供 `/api/ai/generate|rewrite|translate|analyze|suggestions|embedding|stats|usage` 等端点。
  - 使用日志模型 `AIUsageLogModel` 用于计数与成本估算。

- 现有 AI 能力（前端）
  - `aiService` 封装请求与本地配置（模型/API Key），`AIAssistantPage` 提供 NLP 工具入口。

## 任务范围与边界确认

- 首期范围（可交付）
  - 保持并优化现有 NLP 能力（已集成）。
  - 新增智能推荐（基于笔记/任务/项目标签与时效的启发式建议）。
  - 新增轻量预测分析（按历史完成率与到期分布给出趋势与提醒）。

- 非首期范围（规划预留）
  - 计算机视觉端到端（需引入外部 API 或推理服务）。
  - 强个性化推荐（协同过滤、向量检索与反馈闭环）。
  - 完整 A/B 框架与可视化分析面板。

## 需求理解（与现有项目对齐）

- 统一在 `/api/ai` 路由下扩展，复用认证中间件与速率限制。
- 保持 `AIService` 作为模型调用封装；非外部推理场景采用内置统计/启发式算法。
- 所有敏感配置通过环境变量管理；前端 API Key 仅作用户自带模型调用时临时使用。

## 关键问题与澄清

1. 推荐是否必须使用外部模型？
   - 首期不必须，先基于标签/时效/交互频次的启发式，降低成本与复杂度。
2. 预测是否需要严格时序模型？
   - 首期使用近 7–14 天完成率与到期分布的统计推断，后续评估引入 Prophet/LSTM。
3. CV 是否需要在首期上线？
   - 否，先预留接口与文档，待数据与场景明确后上线。
4. A/B 测试是否需要统一框架？
   - 首期以接口参数分组与日志统计实现轻量版本，后续再统一封装。

## 智能决策策略与初始答案

- 优先落地“启发式推荐 + 轻量预测”，保证价值与低风险。
- NLP 统一走 `AIService`，按模型自动选择 OpenAI/SiliconFlow 等提供方。
- 指标先从使用率与响应质量入手，逐步引入转化与留存指标。
