# ALIGNMENT：周报自动生成功能

## 项目上下文分析
- 技术栈与架构：后端 `Node.js + Express (TypeScript)`，前端 `React + Vite`；数据库 `Postgres (Supabase)`；已有 AI 能力在 `AIService/AIController` 中封装并提供端点。
- 现有模块复用：`NoteModel`、`TodoModel`、项目/任务控制器与认证体系可作为数据源；统一鉴权中间件 `authenticateToken` 已在路由层应用。
- 文档与规范：项目已采用 6A 文档体系与「说明文档.md」进度记录；API 使用日志 `AIUsageLogModel` 已建立。

## 需求理解与范围
1) 周报自动生成功能
   - 自动收集一周工作数据：任务完成情况、工时统计、项目进度、关键事项。
   - 支持可自定义模板系统：Markdown/Word 格式模板、占位符替换、样式控制（Word）。
   - 多数据源接入：日历（Google/Apple/Outlook）、内部任务系统（Todo/Task/Project）、Git 提交记录（本地或 GitHub/GitLab API）。
   - 输出规范：生成结构化 `Markdown` 与 `Word (.docx)` 文件，支持历史归档与导出。
2) AI 应用功能集成
   - NLP 优化：语法与风格优化、总结与亮点提取、提升表达专业度与清晰度。
   - 数据驱动建议：自动分析工作数据（目标达成、风险与阻塞）并给出改进建议与优先级推荐。
   - 对话式交互：可在生成后通过对话补充内容，支持问答与自动完善段落。
   - 智能提醒：基于周报与任务优先级给出提醒与行动清单。
3) 非功能性要求
   - 前后端分离、提供清晰 API；考虑数据安全与隐私；支持后续扩展；界面简洁直观，支持历史周报管理与可视化。

## 边界与假设
- 周计算周期：默认周一至周日（可配置），时区默认用户时区（可从 `req.user` 或浏览器获取）。
- 外部数据源：以 Connector 插件化方式接入，初期实现内部数据（Todo/Project）与 Git 提交统计；日历接入以 Token/OAuth 配置占位，后续迭代。
- 模板系统：Markdown 模板为首要目标；Word 使用 `docx` 库生成，支持基本样式与表格。
- 安全与隐私：第三方服务密钥仅在 `.env` 或平台环境中管理；最小化采集与脱敏展示；仅汇总必要数据。

## 智能决策策略（含优先级问题清单）
1) 周定义与数据范围
   - 问题：工作周定义与时区差异？
   - 决策：默认 `week_start=Monday`，允许通过查询参数覆盖；使用用户时区进行时间边界计算。
2) 数据源接入顺序
   - 问题：外部日历与 Git 平台优先级？
   - 决策：优先内部数据（Todo/Project）与 Git 提交（本地或 GitHub 统计）；日历次阶段上线。
3) 模板系统设计
   - 问题：模板语言与占位符格式？
   - 决策：统一使用 `{{placeholder}}` 与管道式格式化（如 `{{completed_count | number}}`）；前端提供模板管理。
4) AI 优化策略
   - 问题：模型选择与成本？
   - 决策：延用现有 `AIService`，优先轻量模型（如 SiliconFlow 平台模型或 OpenAI 小尺寸）；记录使用日志与限流。
5) 生成文件存储
   - 问题：存储位置与导出？
   - 决策：保存元数据与内容快照（Markdown）；Word 生成时提供下载链接；长期存储策略可配置。

## 待澄清问题（建议用户确认）
- 日历平台与授权方式（Google/Apple/Outlook）；
- Git 提交来源（本地与远程仓库选择、统计维度）；
- 周报模板是否需要公司统一规范（标题、章节、配色）；
- 周报的审阅流程（是否需要审批与批注）；
- 历史归档保留时长与敏感字段脱敏策略。

## 阶段性共识（初版）
- 先交付最小可用周报：聚合内部数据 + Git 统计，支持 Markdown 与基本 Word 导出；
- 提供模板管理与一键生成；
- 集成 AI 的内容优化与建议生成；
- API 文档与鉴权齐备；
- 为外部日历与更丰富来源预留扩展接口。
