## 📊 创建的函数列表

创建成功后，你将拥有以下 7 个数据库函数：

### 1. `match_notes` - 向量相似度搜索
**用途**: 基于向量嵌入搜索相似笔记

**参数**:
- `query_embedding`: vector(1536) - 查询向量
- `match_threshold`: float - 相似度阈值（默认 0.7）
- `match_count`: int - 返回数量（默认 10）

**示例**:
```sql
SELECT * FROM match_notes('[0.1, 0.2, ...]'::vector(1536), 0.7, 10);
```

---

### 2. `get_todo_stats` - 待办统计
**用途**: 获取用户的待办事项统计信息

**参数**:
- `user_id_param`: uuid - 用户 ID

**返回字段**:
- `total_count` - 总数
- `completed_count` - 已完成数
- `pending_count` - 待开始数
- `in_progress_count` - 进行中数
- `high_priority_count` - 高优先级数
- `medium_priority_count` - 中优先级数
- `low_priority_count` - 低优先级数
- `overdue_count` - 过期数
- `completion_rate` - 完成率（百分比）

**示例**:
```sql
SELECT * FROM get_todo_stats('12f21e7c-a87c-4c9a-a4e7-30489ace45fa');
```

---

### 3. `get_project_stats` - 项目统计
**用途**: 获取项目的统计信息

**参数**:
- `project_id_param`: uuid - 项目 ID

**返回字段**:
- `note_count` - 笔记数量
- `todo_count` - 待办数量
- `completed_todo_count` - 已完成待办数
- `pending_todo_count` - 待完成待办数
- `member_count` - 成员数量
- `completion_rate` - 完成率

**示例**:
```sql
SELECT * FROM get_project_stats('project-uuid-here');
```

---

### 4. `get_user_activity_stats` - 用户活动统计
**用途**: 获取用户在指定时间范围内的活动统计

**参数**:
- `user_id_param`: uuid - 用户 ID
- `days_param`: int - 统计天数（默认 7）

**返回字段**:
- `notes_created` - 创建的笔记数
- `todos_created` - 创建的待办数
- `todos_completed` - 完成的待办数
- `notes_updated` - 更新的笔记数

**示例**:
```sql
-- 获取最近 7 天的活动
SELECT * FROM get_user_activity_stats('user-uuid-here', 7);

-- 获取最近 30 天的活动
SELECT * FROM get_user_activity_stats('user-uuid-here', 30);
```

---

### 5. `search_notes` - 混合搜索
**用途**: 结合全文搜索和向量搜索

**参数**:
- `search_query`: text - 搜索关键词
- `query_embedding`: vector(1536) - 查询向量（可选）
- `user_id_param`: uuid - 用户 ID（可选）
- `limit_count`: int - 返回数量（默认 20）

**示例**:
```sql
-- 仅全文搜索
SELECT * FROM search_notes('人工智能', NULL, 'user-uuid-here', 20);

-- 混合搜索（需要提供向量）
SELECT * FROM search_notes('人工智能', '[0.1, 0.2, ...]'::vector(1536), 'user-uuid-here', 20);
```

---

### 6. `update_all_search_vectors` - 批量更新搜索向量
**用途**: 批量更新所有笔记的全文搜索向量

**参数**: 无

**返回**: 更新的笔记数量

**示例**:
```sql
SELECT update_all_search_vectors();
```

---

### 7. `get_recent_notes` - 获取最近笔记
**用途**: 获取用户最近创建或更新的笔记

**参数**:
- `user_id_param`: uuid - 用户 ID
- `limit_count`: int - 返回数量（默认 10）

**返回字段**:
- `id` - 笔记 ID
- `title` - 标题
- `content` - 内容
- `created_at` - 创建时间
- `updated_at` - 更新时间
- `is_recent_update` - 是否最近更新（创建后 1 小时内）

**示例**:
```sql
SELECT * FROM get_recent_notes('user-uuid-here', 10);
```

## ✅ 验证函数创建

执行以下 SQL 验证所有函数已创建：

```sql
SELECT 
  routine_name AS function_name,
  pg_get_function_arguments(p.oid) AS parameters,
  obj_description(p.oid) AS description
FROM information_schema.routines r
JOIN pg_proc p ON p.proname = r.routine_name
WHERE routine_schema = 'public'
  AND routine_type = 'FUNCTION'
  AND routine_name IN (
    'match_notes',
    'get_todo_stats',
    'get_project_stats',
    'get_user_activity_stats',
    'search_notes',
    'update_all_search_vectors',
    'get_recent_notes'
  )
ORDER BY routine_name;
```

预期结果应该显示 7 个函数。

## 🆘 故障排除

### 问题 1: 权限错误
```
ERROR: permission denied for schema public
```

**解决方案**: 确保数据库用户有 CREATE FUNCTION 权限

```sql
GRANT ALL ON SCHEMA public TO postgres;
```

---

### 问题 2: 向量扩展未安装
```
ERROR: type "vector" does not exist
```

**解决方案**: 在 Supabase Dashboard 中启用 pgvector 扩展

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

---

### 问题 3: 函数已存在
```
ERROR: function ... already exists
```

**解决方案**: 脚本中已使用 `CREATE OR REPLACE`，如果仍有问题，可以先删除：

```sql
DROP FUNCTION IF EXISTS match_notes;
DROP FUNCTION IF EXISTS get_todo_stats;
-- ... 等等
```

然后重新执行创建脚本。
