## 配置概览

AI Workbench 需要两个 `.env` 文件：

```
AI_Workbench/
├── server/.env          # 后端环境变量（服务器、数据库、API密钥）
└── client/.env          # 前端环境变量（API地址）
```

**配置优先级**: `.env` > 系统环境变量 > 代码默认值

## 必需配置

### 🔴 后端必需配置 (`server/.env`)

这些配置缺失将导致应用无法启动或核心功能失效：

#### 1. Supabase 数据库配置

```bash
# Supabase 项目 URL
SUPABASE_URL=https://your-project-id.supabase.co

# Supabase Anon Key（客户端公开密钥）
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

# Supabase Service Role Key（服务端密钥，权限最高）
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**获取方式**:
1. 登录 [Supabase Dashboard](https://app.supabase.com)
2. 进入你的项目
3. 左侧菜单: Settings → API
4. 复制对应的密钥

**重要提示**:
- ⚠️ `SERVICE_ROLE_KEY` 拥有完全数据库权限，**绝不能**暴露给客户端
- ⚠️ `ANON_KEY` 是公开密钥，可以在前端使用
- ✅ Supabase 通过 Row Level Security (RLS) 保护数据

**验证方法**:
```bash
# 测试连接
curl -X GET "https://your-project-id.supabase.co/rest/v1/" \
  -H "apikey: your-anon-key" \
  -H "Authorization: Bearer your-anon-key"
```

---

#### 2. JWT 认证密钥

```bash
# JWT 签名密钥（至少 32 位随机字符串）
JWT_SECRET=your-super-secret-jwt-key-minimum-32-characters-long

# Token 过期时间（默认 7 天）
JWT_EXPIRES_IN=7d
```

**生成强密钥**:
```bash
# 方法 1: 使用 OpenSSL（推荐）
openssl rand -hex 64

# 方法 2: 使用 Node.js
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"

# 方法 3: 在线生成
# https://www.random.org/strings/
```

**示例输出**:
```
9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4d3e2f1a0b9c8d7e6f5a4b3c2d1e0f9a8b7c6d5e4f3a2b1c0d9e8f
```

**重要提示**:
- ⚠️ 生产环境必须使用不同的密钥
- ⚠️ 密钥泄露需要立即更换（会使所有 Token 失效）
- ✅ 建议至少 64 位十六进制字符

---

#### 3. AI 服务配置

```bash
# SiliconFlow API 密钥（主要 AI 服务提供商）
SILICONFLOW_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxx

# SiliconFlow API 基础 URL
SILICONFLOW_API_BASE_URL=https://api.siliconflow.cn/v1
```

**获取方式**: 参考 [获取 SiliconFlow API 密钥](#获取-siliconflow-api-密钥)

**使用的模型**:
- 文本生成: `Qwen/Qwen2.5-7B-Instruct`
- 代码生成: `deepseek-ai/DeepSeek-Coder-V2-Instruct`
- 长文本: `THUDM/glm-4-9b-chat`

**费用说明**:
- 新用户通常有免费额度
- 按 Token 计费，价格低于 OpenAI
- 支持国内支付方式

---

#### 4. 服务器基础配置

```bash
# Node.js 运行环境
NODE_ENV=development

# 服务器监听端口
PORT=5000
```

**环境说明**:
- `development`: 开发环境，详细日志，热重载
- `production`: 生产环境，优化性能，精简日志
- `test`: 测试环境，用于自动化测试

## 推荐配置

### 🟡 CORS 跨域配置

```bash
# 允许的前端域名（多个用逗号分隔）
CORS_ORIGIN=http://localhost:5173,http://localhost:3000
```

**生产环境示例**:
```bash
CORS_ORIGIN=https://app.yourdomain.com,https://www.yourdomain.com
```

**安全建议**:
- ⚠️ 不要使用通配符 `*`
- ✅ 明确列出所有信任的域名
- ✅ 使用 HTTPS 域名

---

### 🟡 速率限制配置

```bash
# 速率限制时间窗口（毫秒，默认 15 分钟）
RATE_LIMIT_WINDOW_MS=900000

# 时间窗口内最大请求次数
RATE_LIMIT_MAX_REQUESTS=1000
```

**计算示例**:
```
15 分钟 = 900,000 毫秒
1000 次请求 / 15 分钟 ≈ 1.1 次/秒
```

**调整建议**:
- 公共 API: 100-200 次/15分钟
- 内部系统: 1000-5000 次/15分钟
- 开发环境: 可以设置很高或禁用

### 🟢 Git 数据源配置

用于周报功能的 Git 提交统计：

```bash
# 启用 Git 数据源
GIT_DATASOURCE_ENABLED=true

# Git 服务提供商（github/gitlab/gitee）
GIT_PROVIDER=github

# GitHub Personal Access Token
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxx

# GitHub 用户名
GITHUB_USERNAME=your-username

# 监控的仓库列表（逗号分隔）
GITHUB_REPOSITORIES=repo1,repo2,org/repo3
```

**GitHub Token 权限**:
- ✅ `repo` - 访问仓库信息
- ✅ `read:user` - 读取用户信息
- ❌ 不需要写权限

**获取 GitHub Token**:
1. GitHub Settings → Developer settings → Personal access tokens
2. Generate new token (classic)
3. 选择 `repo` 和 `read:user` 权限
4. 复制生成的 token

# 使用外部 AI 分析服务

### 🟢 日志配置

```bash
# 日志级别（error/warn/info/debug）
LOG_LEVEL=info
```

**级别说明**:
- `error`: 仅记录错误
- `warn`: 警告和错误
- `info`: 一般信息、警告和错误（推荐）
- `debug`: 所有日志，包括调试信息（开发用）

## 获取 API 密钥指南

### 获取 Supabase 配置

#### 步骤 1: 注册/登录

1. 访问 https://supabase.com
2. 点击 "Start your project"
3. 使用 GitHub 账号登录（推荐）

#### 步骤 2: 创建项目

1. 点击 "New Project"
2. 填写项目信息：
   - **Name**: ai-workbench
   - **Database Password**: 设置强密码（保存好！）
   - **Region**: 选择距离最近的区域
     - 中国用户推荐: Tokyo (ap-northeast-1)
     - 其他选项: Singapore, Hong Kong
   - **Pricing Plan**: Free（开发测试足够）
3. 点击 "Create new project"
4. 等待 1-2 分钟项目创建完成

#### 步骤 3: 获取配置

1. 项目创建完成后，点击左侧 "Settings"
2. 点击 "API"
3. 找到以下信息：
   - **Project URL** → `SUPABASE_URL`
   - **Project API keys**:
     - `anon` `public` → `SUPABASE_ANON_KEY`
     - `service_role` `secret` → `SUPABASE_SERVICE_ROLE_KEY`
4. 点击 "Copy" 按钮复制

**配置示例**:
```bash
SUPABASE_URL=https://abcdefghijklmn.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 获取 SiliconFlow API 密钥

#### 步骤 1: 注册账号

1. 访问 https://siliconflow.cn
2. 点击 "免费试用" 或 "注册"
3. 填写注册信息：
   - 支持手机号注册
   - 支持邮箱注册
4. 完成验证

#### 步骤 2: 实名认证（可能需要）

1. 登录后进入控制台
2. 根据提示完成实名认证
3. 通常需要身份证信息

#### 步骤 3: 创建 API Key

1. 进入控制台首页
2. 点击左侧 "API 密钥"
3. 点击 "创建新密钥"
4. 填写密钥名称（如：ai-workbench-dev）
5. 点击 "创建"
6. **立即复制密钥**（只显示一次！）

#### 步骤 4: 充值（可选）

1. 新用户通常有免费额度
2. 如需更多额度：
   - 点击 "充值"
   - 选择金额（最低 10 元）
   - 支持支付宝/微信支付

**配置示例**:
```bash
SILICONFLOW_API_KEY=sk-abcdefghijklmnopqrstuvwxyz1234567890
SILICONFLOW_API_BASE_URL=https://api.siliconflow.cn/v1
```

## 安全最佳实践

### ✅ 应该做的

1. **永远不要提交 .env 文件到 Git**
   ```bash
   # .gitignore 中应包含：
   .env
   .env.local
   .env.*.local
   ```

2. **为不同环境使用不同的密钥**
   - 开发环境密钥
   - 测试环境密钥
   - 生产环境密钥

3. **使用强密钥**
   - JWT Secret: 至少 64 位
   - 数据库密码: 至少 16 位，包含大小写、数字、特殊字符

4. **定期轮换密钥**
   - API Key: 每 3-6 个月
   - JWT Secret: 每 6-12 个月
   - 数据库密码: 每 12 个月

5. **限制 CORS 域名**
   ```bash
   # ❌ 不要这样
   CORS_ORIGIN=*
   
   # ✅ 应该这样
   CORS_ORIGIN=https://app.yourdomain.com
   ```

6. **使用 HTTPS**
   - 生产环境必须使用 HTTPS
   - API URL 使用 https://
   - Supabase 默认就是 HTTPS

---

### ❌ 不应该做的

1. **不要在代码中硬编码密钥**
   ```typescript
   // ❌ 错误
   const apiKey = 'sk-1234567890';
   
   // ✅ 正确
   const apiKey = process.env.SILICONFLOW_API_KEY;
   ```

2. **不要在客户端暴露敏感密钥**
   ```typescript
   // ❌ 错误：在前端使用 Service Role Key
   const supabase = createClient(url, serviceRoleKey);
   
   // ✅ 正确：在前端使用 Anon Key
   const supabase = createClient(url, anonKey);
   ```

3. **不要把 .env 文件分享给他人**
   - 使用 .env.example 作为模板
   - 通过安全渠道（如密码管理器）分享密钥

4. **不要在日志中打印密钥**
   ```typescript
   // ❌ 错误
   console.log('API Key:', process.env.SILICONFLOW_API_KEY);
   
   // ✅ 正确
   console.log('API Key loaded:', !!process.env.SILICONFLOW_API_KEY);
   ```

## 常见问题

### Q1: 后端启动时报错 "Supabase config missing"

**原因**: 环境变量未加载或配置错误

**解决方案**:
```bash
# 1. 检查 .env 文件是否存在
ls -la server/.env

# 2. 检查环境变量是否加载
cd server
node -e "require('dotenv').config(); console.log(process.env.SUPABASE_URL)"

# 3. 检查 .env 文件格式
# 确保没有多余的空格、引号
# ✅ 正确：SUPABASE_URL=https://xxx.supabase.co
# ❌ 错误：SUPABASE_URL = "https://xxx.supabase.co"
```

---

### Q2: AI 功能报错 401 Unauthorized

**原因**: API Key 无效或过期

**解决方案**:
```bash
# 1. 验证 API Key 格式
echo $SILICONFLOW_API_KEY
# 应该以 sk- 开头

# 2. 测试 API Key
curl -X POST "https://api.siliconflow.cn/v1/chat/completions" \
  -H "Authorization: Bearer $SILICONFLOW_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen/Qwen2.5-7B-Instruct","messages":[{"role":"user","content":"Hi"}]}'

# 3. 重新生成 API Key
# 登录 SiliconFlow 控制台 → API 密钥 → 创建新密钥
```

---

### Q3: 前端无法连接后端

**原因**: API URL 配置错误

**解决方案**:
```bash
# 1. 检查后端是否启动
curl http://localhost:5000/api/health

# 2. 检查前端配置
cat client/.env
# 确保 VITE_API_URL=http://localhost:5000/api

# 3. 检查 CORS 配置
# server/.env 中应包含前端地址
CORS_ORIGIN=http://localhost:5173

# 4. 清除缓存重启前端
cd client
rm -rf node_modules/.vite
npm run dev
```

---

### Q4: JWT Token 总是过期

**原因**: JWT_SECRET 不一致或 JWT_EXPIRES_IN 配置错误

**解决方案**:
```bash
# 1. 确保 JWT_SECRET 配置正确且一致
cat server/.env | grep JWT_SECRET

# 2. 检查 Token 过期时间
# JWT_EXPIRES_IN=7d  # 7 天
# JWT_EXPIRES_IN=1h  # 1 小时
# JWT_EXPIRES_IN=30m # 30 分钟

# 3. 清除客户端 Token
# 在浏览器控制台执行：
localStorage.removeItem('token')
sessionStorage.clear()
```

---

### Q5: 开发环境正常，生产环境报错

**原因**: 环境变量配置不同

**检查清单**:
- [ ] NODE_ENV=production
- [ ] 数据库 URL 正确
- [ ] CORS_ORIGIN 包含生产域名
- [ ] API URL 使用 HTTPS
- [ ] 所有必需环境变量都已配置
