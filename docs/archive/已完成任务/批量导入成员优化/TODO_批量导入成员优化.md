## 🔄 需要测试

请测试以下场景：

### 1. 批量导入已注册用户
- 输入 `admin@localhost` 和 `123456@123.com`
- 预期：显示为"已注册用户"（绿色），提交后成为正式成员
- 验证：不应该出现在待定成员列表中

### 2. 批量导入未注册邮箱
- 输入一些不存在的邮箱，如 `test1@example.com`
- 预期：显示为"未注册邮箱"（橙色），提交后成为待定成员
- 验证：在项目详情的待定成员列表中可以看到

### 3. 批量导入混合邮箱
- 输入已注册用户、未注册邮箱、已是项目成员的混合列表
- 预期：正确分类显示，每个分类有不同的颜色和说明
- 验证：提交后，已是成员的被跳过，已注册的成为正式成员，未注册的成为待定成员

### 4. 编辑项目时批量导入
- 打开已有项目的编辑弹窗
- 输入项目现有成员的邮箱
- 预期：显示为"已是项目成员"（灰色），提交后被跳过
- 验证：项目成员数量不变

### 5. 待定成员显示
- 查看有待定成员的项目详情
- 预期：只显示尚未注册的待定成员
- 验证：如果待定成员已经注册并成为正式成员，不应该同时出现在两个列表中

## 📝 测试后需要确认的问题

1. **性能**：批量导入 50 个邮箱时，响应速度是否可接受？
2. **UI/UX**：分类显示是否清晰？颜色区分是否明显？
3. **错误处理**：网络错误时是否有合适的提示？
4. **边界情况**：
   - 输入空邮箱列表
   - 输入无效的邮箱格式
   - 输入重复的邮箱
   - 项目没有成员时的显示
