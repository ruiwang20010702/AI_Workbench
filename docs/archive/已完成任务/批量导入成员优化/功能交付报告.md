## 📊 技术实现

### 修改的文件

1. **client/src/components/projects/ProjectCreateModal.tsx**
   - 新增 `MemberChange` 接口（成员变更追踪）
   - 新增 `existingMembers` 状态管理
   - 新增 `loadExistingMembers` 函数
   - 新增成员管理 UI 区域（约 150 行）
   - 新增成员操作处理函数（4个）
   - 修改提交逻辑，处理成员变更

### 核心数据结构

```typescript
interface MemberChange {
  memberId: string;              // 成员ID
  userId: string;                // 用户ID
  email: string;                 // 邮箱
  displayName: string;           // 显示名称
  originalRole: 'admin' | 'member' | 'observer';  // 原始角色
  newRole: 'admin' | 'member' | 'observer';       // 新角色
  action: 'keep' | 'update' | 'remove';           // 操作类型
}
```

### 核心函数

1. **loadExistingMembers** - 加载现有成员
2. **handleMemberRoleChange** - 修改角色
3. **handleMemberRemove** - 删除成员
4. **handleMemberRestore** - 恢复成员
5. **processMemberChanges** - 批量处理变更

### 后端部署

**无需修改**，使用现有 API：
- `GET /api/projects/:id/members` - 获取成员列表

## ⚠️ 注意事项

### 权限要求

- 只有项目管理员可以修改成员
- 后端已有权限验证，前端无需额外处理

### 已知限制

1. **批量操作性能**
   - 当前逐个处理成员变更
   - 如果成员数量超过 100，建议优化为批量 API

2. **实时同步**
   - 成员变更不会实时推送给其他用户
   - 需要刷新页面才能看到最新成员列表

3. **删除限制**
   - 无法删除项目创建者
   - 无法删除自己（如果是唯一管理员）

## 🐛 问题排查

### 常见问题

1. **看不到"现有成员管理"区域**
   - 原因：只在编辑模式显示
   - 解决：确保点击"编辑"而非"创建项目"

2. **成员列表一直加载中**
   - 原因：API 请求失败
   - 解决：检查控制台网络请求

3. **提交后变更未生效**
   - 原因：后端 API 调用失败
   - 解决：查看控制台错误日志

详细排查指南：[成员管理功能测试指南.md](./成员管理功能测试指南.md)
