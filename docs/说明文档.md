# AI_Workbench 说明文档

> 本文档为项目全生命周期唯一管理载体，包含项目规划、实施方案与进度记录。每次启动或调整项目，需先阅读并更新本文档。

## 项目规划

- 项目目标
  - 在现有工作台中引入可落地的 AI 应用能力，提升效率与质量。
  - 优先交付：自然语言能力（文本生成/改写/翻译/分析）、智能推荐与轻量预测分析。
  - 后续规划：计算机视觉（图像识别/内容审核）与更高级个性化系统。

- 业务范围
  - 面向现有模块：笔记、任务、项目管理与通知。
  - AI 增强点：内容创作辅助、结构化提取、标签/标题建议、个性化推荐、进度与风险预测。

- 环境与部署
  - 前后端已部署至 Vercel，数据库使用 Supabase（Postgres）。
  - 敏感配置通过环境变量管理（详见 `.env.example` 与 Vercel/Supabase 项目环境）。

- 成功度量（ROI 指标）
  - 写作辅助使用次数与节省时间（人均每次 30–120 秒）。
  - 推荐点击转化率（被推荐的笔记/任务的访问或处理率）。
  - 预测提醒命中率（在到期前 48h 完成的任务比例提升）。
  - 用户留存与活跃度（周/月活跃提升与功能使用覆盖率）。

## 实施方案

1) 需求与对齐
   - 建立 6A 文档：ALIGNMENT、CONSENSUS、DESIGN、TASK、ACCEPTANCE、FINAL、TODO。
   - 明确首批交付范围：NLP 能力完善、智能推荐、轻量预测分析。

2) 技术选型与架构
   - 服务端采用 Node.js + Express（TypeScript），遵循现有控制器/服务/模型分层。
   - NLP 调用优先 SiliconFlow/OpenAI（已集成），统一在 `AIService` 中封装。
   - 推荐/预测首期以启发式与统计方法实现，逐步替换为嵌入向量/协同过滤/时序模型。

3) 集成与交互
   - 新增后端 API：`/api/ai/recommendations`、`/api/ai/predict`。
   - 前端服务层新增方法（不改 UI）：`aiService.getRecommendations`、`aiService.getPredictiveInsights`。
   - 后续在 `AIAssistantPage` 增加工具入口与可视化（待排期）。

4) 数据与隐私
   - 基于 Supabase/Postgres 的用户数据（笔记、任务、项目）进行匿名统计与个性化推荐。
   - 遵循最小化原则，敏感信息不出库、不持久化第三方；API Key 仅存于环境变量。

5) 测试与评估
   - 指标：响应时间、可用性（错误率）、准确性（主观/客观）、转化率。
   - A/B 测试：推荐策略与提示词对比实验，按用户分组；收敛后固化策略。

## 风险与应对

- 第三方模型速率与成本：设置速率限制与使用日志、分级模型选择。
- 数据质量不足：先用启发式与统计，逐步引入向量化与用户反馈闭环。
- 部署变更与密钥管理：统一 `.env` 与平台环境变量，严禁提交密钥到仓库。
