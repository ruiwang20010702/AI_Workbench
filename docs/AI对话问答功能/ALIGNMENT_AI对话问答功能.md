## 1. 原始需求

用户希望在AI助手中添加**对话式问答功能**，使AI能够：
- 回答关于用户个人数据的问题（笔记、项目、待办事项等）
- 支持自然语言查询，例如：
  - "我最近的项目是什么？"
  - "本周完成了哪些任务？"
  - "有哪些高优先级的待办事项？"
  - "关于XX的笔记在哪里？"

## 2. 项目上下文分析

### 2.1 现有系统架构

#### 技术栈
- **前端**: React + TypeScript + TailwindCSS
- **后端**: Node.js + Express + TypeScript
- **数据库**: PostgreSQL (通过Supabase)
- **AI服务**: 硅基流动API (SiliconFlow) + 支持多模型切换

#### 现有AI功能
当前AI助手已实现的功能（`AIAssistantPage.tsx`）：
1. ✅ 文本生成 (`generate`)
2. ✅ 文本改写 (`rewrite`)
3. ✅ 文本翻译 (`translate`)
4. ✅ 文本分析 (`analyze`)
5. ✅ 文本摘要 (`summarize`)
6. ✅ 智能推荐 (`recommendations`) - 基于启发式算法
7. ✅ 预测分析 (`predictions`) - 基于历史数据统计

**缺失功能**: 对话式问答 (Conversational Q&A)

#### 数据模型
系统已有完整的数据模型：
- **笔记** (`notes`): 标题、内容、标签、笔记本、收藏、归档
- **项目** (`projects`): 名称、描述、状态、优先级、任务统计
- **待办** (`todos`): 标题、描述、状态、优先级、截止日期
- **AI使用日志** (`ai_usage_logs`): 记录所有AI操作

#### 现有API端点
- `GET /api/notes` - 获取笔记列表（支持搜索、标签过滤）
- `GET /api/projects` - 获取项目列表（支持状态、优先级过滤）
- `GET /api/todos` - 获取待办列表（支持状态、优先级过滤）
- `POST /api/ai/generate` - AI文本生成
- `GET /api/ai/recommendations` - 智能推荐
- `GET /api/ai/predict` - 预测分析

## 3. 需求理解

### 3.1 核心功能
实现一个**RAG（检索增强生成）系统**，使AI助手能够：

1. **理解用户问题**
   - 解析自然语言问题
   - 识别问题意图（查询笔记、项目、待办等）
   - 提取关键信息（时间范围、优先级、标签等）

2. **检索相关数据**
   - 根据问题意图查询数据库
   - 获取用户的笔记、项目、待办数据
   - 支持时间范围过滤（最近、本周、本月等）
   - 支持条件过滤（优先级、状态、标签等）

3. **生成智能回答**
   - 将检索到的数据作为上下文
   - 调用AI模型生成自然语言回答
   - 回答准确、简洁、有用

4. **多轮对话支持**
   - 保持对话上下文
   - 支持追问和澄清
   - 记录对话历史

### 3.2 用户场景示例

#### 场景1: 查询最近的项目
```
用户: "我最近的项目是什么？"
系统: 
1. 识别意图: 查询项目
2. 检索数据: 获取最近更新的项目（按updated_at排序，取前5个）
3. 生成回答: "您最近的项目有：
   - [项目A] - 进行中，优先级高
   - [项目B] - 已完成，优先级中
   - ..."
```

#### 场景2: 查询待办事项
```
用户: "有哪些高优先级的待办事项？"
系统:
1. 识别意图: 查询待办
2. 检索数据: 获取priority='高'且completed=false的待办
3. 生成回答: "您有3个高优先级的待办事项：
   1. [任务A] - 截止日期: 2025-11-05
   2. [任务B] - 截止日期: 2025-11-03
   3. ..."
```

#### 场景3: 搜索笔记
```
用户: "关于React的笔记在哪里？"
系统:
1. 识别意图: 搜索笔记
2. 检索数据: 搜索标题或内容包含"React"的笔记
3. 生成回答: "找到2条关于React的笔记：
   1. [React Hooks学习笔记] - 更新于2025-10-28
   2. [React性能优化] - 更新于2025-10-25"
```

#### 场景4: 统计查询
```
用户: "本周完成了多少任务？"
系统:
1. 识别意图: 统计待办
2. 检索数据: 获取本周completed=true的待办数量
3. 生成回答: "本周您完成了12个任务，完成率达到75%。做得很好！"
```

## 5. 疑问澄清

### 5.1 已确定的决策

#### Q1: 是否需要实现语义搜索（向量检索）？
**决策**: 暂不实现  
**理由**: 
- 数据库已有`embedding`字段但未使用
- 实现向量检索需要额外配置和成本
- 第一版使用关键词搜索即可满足需求
- 可在后续版本中添加

#### Q2: 是否支持修改数据（创建、更新、删除）？
**决策**: 暂不支持  
**理由**:
- 第一版专注于查询功能
- 修改操作需要更复杂的权限和确认机制
- 避免AI误操作导致数据丢失
- 可在后续版本中添加

#### Q3: 对话历史存储在哪里？
**决策**: 前端localStorage + 后端AI使用日志  
**理由**:
- 对话历史存储在localStorage，方便快速加载
- AI使用记录存储在数据库，用于统计和审计
- 不需要额外的对话表

#### Q4: 如何识别问题意图？
**决策**: 使用AI模型进行意图识别  
**理由**:
- 利用AI的自然语言理解能力
- 不需要手动编写复杂的规则
- 灵活性高，易于扩展

### 5.2 需要用户确认的问题

#### Q5: 对话历史保留多久？
**选项**:
- A. 永久保留（直到用户手动清除）
- B. 保留最近100条
- C. 保留最近7天

**建议**: 选项B - 保留最近100条  
**理由**: 平衡性能和用户体验

#### Q6: 单次查询返回的数据量限制？
**选项**:
- A. 最多5条
- B. 最多10条
- C. 最多20条

**建议**: 选项B - 最多10条  
**理由**: 避免回答过长，保持可读性

## 6. 技术实现方案概要

### 6.1 架构设计
```
用户问题 → 前端AI助手 → 后端问答API → 意图识别 → 数据检索 → AI生成回答 → 返回前端
```

### 6.2 核心组件
1. **前端**: 
   - 新增"智能问答"工具
   - 对话界面（已有）
   - 对话历史管理

2. **后端**:
   - 新增`POST /api/ai/chat`端点
   - 意图识别服务
   - 数据检索服务
   - 回答生成服务

3. **数据库**:
   - 复用现有表结构
   - AI使用日志记录`action_type='assistant_qa'`

### 6.3 技术选型
- **意图识别**: 使用AI模型（通过prompt engineering）
- **数据检索**: 使用现有的Model层方法
- **回答生成**: 使用现有的AIService.generateText方法
- **对话管理**: 前端localStorage + 后端无状态

## 8. 风险评估

### 8.1 技术风险
- **风险**: AI模型可能无法准确识别意图
- **缓解**: 使用精心设计的prompt，提供示例
- **影响**: 中等

- **风险**: 数据量大时查询性能可能下降
- **缓解**: 限制返回数量，添加索引
- **影响**: 低

### 8.2 用户体验风险
- **风险**: AI回答可能不够准确
- **缓解**: 在回答中提供数据来源，允许用户验证
- **影响**: 中等
